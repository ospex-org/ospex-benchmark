# Market-open B2: admission and producer

**Source-only; reviewed at `f52f779`, then corrected under explicit merge authorization. Nothing installed or enabled.** This is a library boundary, not a new service or a relaunch command. Campaign/#122/#123 remain alternatives. B3 execution and B4 consumer/publication admission remain closed.

## API and authority

`MarketOpenProducer` accepts one immutable cohort name/date, an absolute local evidence root, a cumulative USD-micro cap, and the pinned roster's transport adapters. It does not load credentials, construct providers, query Supabase, or publish. `observe(observation)` synchronously commits admission and schedules that single market. `admit` commits without dispatch (also the crash boundary) and reports the durable refusal/reason for halted or over-cap claims; `recover` schedules only unsent claims. `drain` waits for all owned jobs; `close` drains before releasing its writer lock. Caller-owned adapter maps, methods and artifact-root options are captured before admission.

The observation boundary is trusted: callers supply the complete history result for exactly one game/market and its real first eligible observation time. No current-odds or full-board completion adapter is substituted. Source-acquisition/activation wiring must preserve this contract; this PR does not install a Supabase reader. B1 validates/prepares the singleton request and immutable opener. An existing admitted event is reconstructed from its ORIGINAL persisted preparation, not the newest observation or source row.

## Timestamps, not trip wires

Record milestones and monitor elapsed time; never refuse or halt work merely for taking longer than a configured duration. First pitch and spend caps remain the hard scheduling/accounting stops. Identity, durable evidence, single-writer integrity and unknown-spend protections remain prerequisites to safe spending, not elapsed-time policies.

`observationToSendWarningMs` is configuration, **default 120,000 ms (two minutes)**. Equality is not a warning; any greater initial/repair lag is recorded as `lagWarning`, not a refusal, retry, reservation operation or cohort halt. `MARKET_OPEN_MONITORING_DEFAULTS` supplies the warning default. Monitoring configuration is recorded per run, not included in the admission-policy hash: changing a warning threshold on replay cannot trip a config-identity stop or change claims/reservations. Accepted B1 cohort-policy bytes stay unchanged. Two independent market workers and 6,000 maximum output tokens are unchanged. The arbitrary 60-second producer attempt timeout is removed: the shared transport/acceptance deadline is the remaining time to first pitch.

- `run_meta.marketOpenTiming` records the opener's actual history `captured_at` (`openerPresentAt`, not an invented upstream publication time), original `firstObservedAt`, `claimedAt`, and each arm/role's durable-intent, actual send and response times, observation-to-send milliseconds and warning flag.
- Sample `claimedAt` at the claim boundary and persist it in the same atomic claim/reservation transition. Sample the send again after intent fsync, immediately before `adapter.chat`; lag uses that actual reading, not the earlier intent timestamp. First-pitch and spend checks still run there.
- `status()` returns a read-only heartbeat payload with each fire's timing, including in-flight sends before a response is available. Settled request/response readings are durable in existing attempt evidence. A crash between send and evidence leaves an uncertain send, not an invented timestamp; the durable intent and unknown-spend recovery remain authoritative.
- Sample `artifactInstalledAt` only AFTER immutable installation/fsync; after successful verification persist it in the existing completion journal entry. The pre-install run record necessarily carries `artifactInstalledAt: null`; join the completion journal/status by event and artifact hash for that final hop. Never rewrite immutable records to insert their own future installation time.
- Queued/recovered work keeps its first observation, claim time, opener and identity. It continues before first pitch regardless of elapsed lag, including late repairs. There is no lag-refusal path or lag-refusal reservation handling. Cumulative reservations are still never recycled for other work.
- B3/B4 must wire `status()` into their existing heartbeat/status surfaces; this library installs no monitor or service. Status applies the current configured warning threshold to the preserved timestamps; immutable run records retain the threshold used when written. Changing monitoring configuration is not an admission or replay gate.

## Single writer, atomicity, accounting

One private **local Linux** root is the authoritative ledger for a cohort. The host must provision that one root consistently; copying it or supplying another root is not an authorized second writer. Shared/network filesystems, multi-host writers and cross-PID-namespace sharing are unsupported. Process identity requires host-visible `/proc` and util-linux `/usr/bin/flock`. The runtime does NOT detect Linux mount classes: activation must independently verify a supported local filesystem (not NFS/SMB/9p/DrvFs). Filesystem-type enforcement/pinning remains a tracked deployment-hardening follow-up. An exclusive `.writer-lock` directory, owner nonce/inode verification and a lifetime kernel guard fence concurrent writers. Owner death is proved from boot ID, PID existence and process start ticks, never elapsed time or mtime. Persistence uncertainty still poisons the handle. See [local process lock protocol](LOCAL-PROCESS-LOCK.md).

The store uses the campaign sink's `installBytesNoClobber`/`nodeArtifactFs`: write temporary bytes, file fsync, no-clobber hard link, directory fsync. Each canonical hash-chained journal operation commits the whole per-market claim, original preparation, initial+repair slots and cumulative reservation in one install. Replays verify canonical shapes, sequence, hashes, pinned config and artifacts; malformed/truncated/drifting roots fail closed. The chain detects damage, not an adversary allowed to rewrite the entire private root.

Each initial/repair slot has a durable intent before send and immutable evidence after settlement, before validation or repair. The shared runner owns request/response timestamps, raw usage, provider response envelope, search audit, request parameters and outcome. The producer always applies the shared **billable** conservative pricing/guard path—even to the synthetic test adapters. Missing usage or search accounting is unknown, never B1's mock-only known-zero escape. Known costs use the pinned price table; over-reservation actuals are not clamped. Unknown spend or a per-attempt/cumulative breach halts all future initial/repair sends and admissions; already in-flight responses still settle and retain evidence.

The scheduler has two independent market workers; each invokes the existing runner for ONE prepared market and its fixed roster concurrently. It does not call the runner's legacy multi-game serial loop. Thus a slow moneyline does not block a total; a third event queues under the bound. No worker clears a halt or retries an uncertain send.

## Record and artifact boundary

The shared `buildRecords` calls `marketOpenRecordBoundary` unconditionally. B1 permanent identity checks remain owned by preparation; fixture-only permission is separate from producer permission. The producer's store-owned receipt binds the exact prepared run AND exact envelope, with each recorded send matching settled journal evidence. Copying a receipt/envelope, squatting the namespace, dropping provenance, or changing run/cohort/build/roster/request/fetch timestamps cannot bypass it.

`bundle_game.sourceOddsReference` is an explicit `market-open-history-v1` reference to that run's `run_meta.marketOpen.source`, bound to event, game, market, opener and hashes. `sourceOddsRows` remains empty: no invented `CurrentOddsRow`. Legacy records keep their prior shape. B4 must validate this reference before consumer admission AND require `mode === 'live'` / `clockMode === 'wall'`; labelled dry-run/synthetic-fixture records are never production authority.

The producer installs one immutable, canonical `<eventId>.json` containing policy, shared records, spend verdict and admission evidence. Only after installation and artifact read/hash/fsync verification does a terminal journal entry attach it and permit clean completion. Invalid arm outcomes remain `failed`; accounting uncertainty remains `unknown`. Neither is promoted to `completed` merely because an artifact exists. Consumer discovery and trusted public publication are not added here.

## Recovery and stop semantics

- `claimed`, no attempt intent: rebuild the exact persisted preparation and claim time; record original observation-to-send lag and continue before first pitch. At/after first pitch refuse without sending, never because of elapsed lag.
- `running` after interruption, including settled attempts but no completion: persist `unknown`, retain the reservation and halt the cohort. Never resend or recreate an identity to repair an uncertain run.
- `completed`/`failed`/`unknown`/`refused`: stable replay; no provider dispatch. A completed artifact must still match its hash and durable path on reopening.
- An artifact installed before a lost terminal commit is orphan evidence, **not completion authority**. Preserve it for offline reconciliation; this version conservatively halts instead of automatically adopting it.
- A provably dead writer marker is reclaimed automatically, with one timestamped recovery record and the old marker archived intact. Same-boot live owners and unprovable owner identity refuse with the specific cause. There is no timeout-based takeover.
- Journal/config/artifact damage or fsync ambiguity: stop. Preserve the root and reconcile offline with all writers stopped. Lock recovery is not permission to clear a persisted halt, edit the journal or retry an uncertain send. No online unknown-spend override API exists.

SIGKILL tests kill disposable synthetic child processes at claim and send, then reopen unattended after `waitpid` without manual lock deletion. Unsent claims recover with their original clock; interrupted sends recover unknown with zero retries. These tests do not claim power-loss or network-filesystem conformance.
